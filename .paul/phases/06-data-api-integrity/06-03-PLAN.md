<task type="auto">
  <name>Task 2: Add deploy rollback on verification failure</name>
  <files>.github/workflows/_deploy-backend.yml</files>
  <action>
    Add a rollback step after the "Verify deployment" step in `.github/workflows/_deploy-backend.yml`:

    ```yaml
    - name: Rollback on verification failure
      if: failure() && steps.deploy.outcome == 'success'
      run: |
        echo "Verification failed — rolling back to previous revision"
        REVISIONS=$(gcloud run revisions list \
          --service=${{ vars.CLOUD_RUN_SERVICE }} \
          --region=${{ vars.GCP_REGION }} \
          --format="value(name)" \
          --sort-by="~createTime" \
          --limit=2)
        REVISION_COUNT=$(echo "$REVISIONS" | wc -l | tr -d ' ')
        if [ "$REVISION_COUNT" -ge 2 ]; then
          PREV_REVISION=$(echo "$REVISIONS" | tail -1)
          gcloud run services update-traffic ${{ vars.CLOUD_RUN_SERVICE }} \
            --region=${{ vars.GCP_REGION }} \
            --to-revisions="$PREV_REVISION=100"
          echo "Traffic routed to previous revision: $PREV_REVISION"
        else
          echo "No previous revision found — first deploy, skipping rollback"
        fi
    ```

    <!-- audit-added: count-based revision check instead of tail-1 on potentially single-line output -->

    The condition `failure() && steps.deploy.outcome == 'success'` ensures:
    - Rollback only triggers when deploy succeeded but verification failed (not on build/push failures)
    - First deploy correctly detected by revision count < 2 (avoids routing traffic to the broken revision itself)

    Avoid: Do NOT add `id:` to the verify step — use the deploy step's outcome as the gate since we want to roll back only when the new revision is actually serving.
    Avoid: Do NOT change any existing steps.
  </action>
  <verify>

    - Rollback step is present after "Verify deployment"
    - Rollback step condition is `failure() && steps.deploy.outcome == 'success'`
    - Rollback uses revision count check (not just `-n` on tail output) <!-- audit-added -->
  </verify>
  <done>AC-3 and AC-4 satisfied: Rollback automatically triggers on verify failure, gracefully handles first deploy</done>
