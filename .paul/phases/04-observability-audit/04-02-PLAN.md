<objective>
## Goal
Create an append-only audit_log table and record_audit_event() function, then wire audit calls into all admin account mutations — enabling forensic investigation of "who did what to whom."

## Purpose
Administrative actions (account creation, role changes, password resets, deletions) currently leave no trace. This makes compliance auditing, insider threat investigation, and incident reconstruction impossible. This plan addresses finding F-05-001.

## Output
- Migration 029: `audit_log` table with indexes
- `backend/app/core/audit.py` — `record_audit_event()` function
- `backend/app/modules/accounts/router.py` — audit calls wired into all mutation endpoints
- Unit and integration tests
</objective>

## AC-3: Account Creation Audited
```gherkin
Given an admin creates a new account via POST /api/v1/accounts
When the account is successfully created
Then an audit_log row is recorded with action="account.create", the admin as actor, and the new user as target
```

## AC-4: Role Change Audited
```gherkin
Given an admin changes a user's role via PATCH /api/v1/accounts/{id}/role
When the role change succeeds
Then an audit_log row is recorded with action="account.role_change", the admin as actor, and details containing old_role and new_role
```

## AC-5: Password Reset Audited
```gherkin
Given an admin resets a user's password via POST /api/v1/accounts/{id}/reset-password
When the password reset succeeds
Then an audit_log row is recorded with action="account.password_reset", the admin as actor, and the target user
```

## AC-6: Account Deletion Audited
```gherkin
Given an admin deletes an account via DELETE /api/v1/accounts/{id}
When the deletion succeeds
Then an audit_log row is recorded with action="account.delete", the admin as actor, and details containing the deleted user's email and role
```

## AC-7: Audit Failure Does Not Break Mutation Response <!-- audit-added -->
```gherkin
Given an admin mutation succeeds (account created, role changed, etc.)
When the audit INSERT fails (connection error, constraint violation, etc.)
Then the HTTP response still returns the successful mutation result
And an ERROR-level log is emitted containing the audit failure details and the action that was not audited
```
