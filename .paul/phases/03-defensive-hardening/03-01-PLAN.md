<acceptance_criteria>

## AC-1: Container runs as non-root user
```gherkin
Given the backend Docker image is built
When the container starts
Then the process runs as UID 1001 (appuser), not root
```

## AC-2: Unhandled exceptions return generic error
```gherkin
Given an unhandled exception occurs in any endpoint
When the error propagates to FastAPI
Then the client receives 500 with {"error": "Internal server error"} and no stack trace, file paths, or library versions
```

## AC-3: Email domain validation denies when unconfigured
```gherkin
Given EMAIL_ALLOWED_DOMAINS is empty or unset
When a user sends an email request with any recipient
Then the request is rejected with a clear error message (fail-closed)
```

<!-- audit-added: AC-6, AC-7 -->
## AC-6: Exception handler has regression test
```gherkin
Given the global exception handler is registered
When an unhandled exception is triggered in a test
Then the test asserts response status is 500 and body contains no traceback, file paths, or internal details
```

## AC-7: Email fail-closed has regression test
```gherkin
Given EMAIL_ALLOWED_DOMAINS is empty or unset in test environment
When a SendEmailRequest is constructed with any recipient
Then validation raises ValueError with message indicating configuration required
```

## AC-4: ScoringRequest requires explicit verdict
```gherkin
Given a POST to the scoring endpoint
When the request body omits the verdict field
Then the server returns 422 (validation error), not a default empty string
```

## AC-5: SQL sort allowlist remains in place
```gherkin
Given the list_evaluations function in evaluations.py
When called with any sort_by value not in {"created_at", "final_score"}
Then a ValueError is raised before the SQL query executes
```

<task type="auto">
  <name>Task 2: Add global exception handler and fail-closed email validation</name>
  <files>backend/app/main.py, backend/app/modules/email/schemas.py</files>
  <action>
    **main.py — Global exception handler:**
    1. Add a catch-all `Exception` handler registered via `app.add_exception_handler(Exception, ...)`
    2. The handler must:
       - Log the full exception with `logger.exception(...)` including request path and method
       - Return JSONResponse with status 500 and body: `{"error": "Internal server error"}`
       - NOT include stack trace, file paths, or internal details in the response
    3. Register it AFTER the AppException handler (line 54)
    4. Import `Request` from fastapi (already available via FastAPI)

    **email/schemas.py — Fail-closed domain validation:**
    1. In `validate_recipient_domains`, change the early return when `allowed_raw` is empty/None:
       - Current: `if not allowed_raw: return self` (fail-open — allows any domain)
       - New: `if not allowed_raw: raise ValueError("Email sending is not configured. Set EMAIL_ALLOWED_DOMAINS.")`
    2. This enforces the fail-closed pattern established in Phase 1 (OIDC allowlist)

    <!-- audit-added: test requirements for exception handler and email fail-closed -->

    1. Write a test that triggers an unhandled exception through the FastAPI test client

       - Assert response status is 500
       - Assert response body contains `{"error": "Internal server error"}`
       - Assert response body does NOT contain "Traceback", "File ", or ".py"
    2. This test prevents regression — if someone removes the handler, the test fails

    **Test: Email fail-closed validation (in test_schemas.py or new test):**

       - Construct SendEmailRequest with any valid recipient

    2. Write a test with EMAIL_ALLOWED_DOMAINS set to a valid domain

       - Assert validation passes

    3. In `infrastructure/terraform/variables.tf`, add root-level variables:
