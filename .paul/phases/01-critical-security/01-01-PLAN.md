<acceptance_criteria>

## AC-1: OIDC Audience Validation Activated
```gherkin
Given the Cloud Run service is deployed with CLOUD_RUN_URL and ALLOWED_SCHEDULER_EMAILS env vars
When Cloud Scheduler sends an OIDC token
Then the token audience is validated against the service URL
And only the configured scheduler service account email is accepted
```

## AC-2: OIDC Fail-Closed When Unconfigured
```gherkin
Given allowed_scheduler_emails is empty or not set
When any OIDC token is presented (even with valid signature)
Then authentication is rejected with AUTH_TOKEN_INVALID
And a warning is logged: "OIDC auth rejected: ALLOWED_SCHEDULER_EMAILS not configured"
```

## AC-3: Health Check Verifies DB Connectivity
```gherkin
Given the application is running
When GET /health is called and the database is reachable
Then response is 200 with {"status": "healthy", "checks": {"database": "ok"}}

Given the database pool is unavailable or connection fails
When GET /health is called
Then response is 503 with {"status": "unhealthy", "checks": {"database": "unreachable"}}
And the actual exception is logged at WARNING level for debugging
```
<!-- audit-added: strengthened to require exception logging for post-incident debugging -->

## AC-4: Deploy Verification Uses Health Endpoint
```gherkin
Given a backend deployment completes
When the CI verification step runs
Then it hits /health (not /docs)
And asserts "status": "healthy" in the JSON response
And fails the workflow if health check returns unhealthy
```

## AC-5: GCS Buckets Block Public Access
```gherkin
Given the Terraform configuration is applied
When the GCS upload bucket is created
Then public_access_prevention is set to "enforced"
```

## AC-6: CORS Origins Are Environment-Driven
```gherkin
Given the application starts with CORS_ORIGINS env var set
When a browser preflight request arrives from a listed origin
Then the Access-Control-Allow-Origin header matches

Given CORS_ORIGINS is not set (local dev)
When a request arrives from localhost:5173
Then it is allowed (default fallback)
```

    Replace the static health check with one that verifies DB connectivity:
    ```python
    @app.get("/health")
    async def health_check() -> dict:
        """Health check — verifies DB connectivity for Cloud Run readiness."""
        checks: dict[str, str] = {}
        healthy = True

        if db.pool:
            try:
                async with db.connection() as conn:
                    await conn.fetchval("SELECT 1")
                checks["database"] = "ok"
            except Exception:
                logger.warning("Health check DB probe failed", exc_info=True)  # audit-added
                checks["database"] = "unreachable"
                healthy = False
        else:
            checks["database"] = "not_configured"

        if not healthy:
            return JSONResponse(
                status_code=503,
                content={"status": "unhealthy", "checks": checks},
            )
        return {"status": "healthy", "checks": checks}
    ```
    Note: `logger` already exists in main.py scope from `import logging` — add `logger = logging.getLogger(__name__)` if not present.
    <!-- audit-added: log actual exception for post-incident debugging -->
