## Successes & Strengths

1. **Fallback-first design eliminated refactoring risk** — `rules: dict | None = None` with hardcoded defaults as fallback meant zero chance of breaking existing behavior during the scoring calculator refactoring
2. **Clean 3-story decomposition (view → edit → apply)** — each story built naturally on the prior with no rework needed between stories
3. **HIGH code review issues trending down** — from ~3.8/story (Epic 2) → ~6/story (Epic 3) → ~7/story (Epic 4) → ~1.3/story (Epic 5)
4. **Helper extraction pattern** — `_get_rule_category()` and `_get_rule_value()` created a repeatable, consistent pattern across all 10 scoring categories
5. **Dynamic E-column benchmarks** — bonus improvement during refactoring; benchmark strings now use actual threshold values from rules
6. **Reuse of existing infrastructure** — `get_rules_by_template()` query from Story 5.1 reused directly in Story 5.3, no new DB queries needed
7. **Test suite grew** — 855+ automated tests, zero regressions throughout the epic

---

## Challenges & Growth Areas

1. **Story 5.2 concentrated 3 HIGH code review issues:**
   - Dialog caught ALL errors as "Incorrect password" (server save failures misreported)
   - Inline validation marked complete but not actually implemented
   - Task falsely marked done before AC was met
2. **Recurring review themes persist across epics:** type precision (`str` → `Literal`), file list gaps in story specs — same patterns flagged in Epic 3, 4, and now 5
3. **Code review issue rate on Story 5.2 (11 issues)** was highest in the epic, though overall trend is improving

---

## Key Insights

1. **Code review is working as the safety net** — all issues caught before production, no need for additional formal gates
2. **Scoring calculator documentation (A3) proved valuable** — the pre-Epic 5 snapshot served as reference during the refactoring
3. **Pure function pattern continues to pay dividends** — easy to test, easy to refactor, easy to maintain
4. **3-story progression is an effective decomposition strategy** — view → edit → apply gave clean boundaries and natural progression
5. **Seed data = source of truth** — migration 010 seed data served as both configuration and living documentation of all thresholds
