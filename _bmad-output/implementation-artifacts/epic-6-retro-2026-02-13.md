## Root Cause Analysis

### Primary Finding: Epic Did Not Deliver Its Core Promise

Epic 6 is called "Production Deployment & Launch." The expected outcome was a working app, deployed, that the BD team can use. What was delivered instead:

- Terraform configs (never applied to production by dev agents)
- CI/CD workflows (never triggered for a real deploy)
- Smoke tests (tested dev/localhost, not production)
- Documentation (describing assumed behavior, not verified behavior)

Mr. Door had to deploy it himself, debug it himself, and fix bugs himself.

### Systemic Pattern: "Works in Dev, Broken in Production"

Every piece of work in Epic 6 was built and tested in a local/dev context but never verified against an actual deployed environment.

| Story | What Was Built | What Was Missed |
|-------|---------------|-----------------|
| 6-1 Infrastructure | Terraform configs, validate passed | Never applied to production |
| 6-2 CI/CD | Workflows written, YAML valid | Never triggered for real deploy |
| 6-3 Smoke Tests | 19 tests all passing | Tests ran against dev, not production |
| 6-4 Onboarding | Scripts + docs created | Scripts never executed, docs unverified |

### Production Bugs Found by Mr. Door (8 commits)

### Why Code Review Didn't Catch This

- 28 code review issues found — all about code quality (types, error handling, structure)
- Zero findings about "has this been deployed and tested?"
- Code review validates code correctness, not operational readiness
- No step in the review process asks "did you verify this works when deployed?"

### Documentation Written Before Verification

The onboarding guide, validation templates, and launch readiness document describe how the app *should* work, not how it *actually* works. They were written before anyone verified the deployed app functions. This gives false confidence — BD team members following the guide would hit bugs with no guidance on what's wrong.

## Challenges & Critical Failures

1. **No actual deployment by dev agents** — The "Production Deployment & Launch" epic never deployed to production
2. **Mr. Door as last line of defense** — Project Lead discovered and personally fixed 8 production-blocking bugs
3. **"Tests passing" ≠ "It works"** — 948 automated tests + 19 smoke tests all passing, yet app broken when deployed
4. **Documentation describes fiction** — Docs written assuming everything works; real bugs undocumented
5. **No Definition of Done for deployment stories** — Team's implicit DoD was code-complete, not production-verified
6. **Known remaining bugs** — Not all functionality tested; additional bugs expected

---

## Key Insights

1. **The team's definition of "done" is incomplete** — "Tests pass + code review passes" is insufficient for deployment stories. Must include "deployed and manually verified."
2. **Code quality ≠ product quality** — Clean code that doesn't work in production is not quality. The gap between dev and production must be part of the verification process.
3. **Documentation should follow verification, not precede it** — Writing docs before verifying the app works creates false confidence and incorrect documentation.
4. **Dev agents cannot fully verify deployment stories** — If a story requires cloud access, credentials, or manual deployment, completion notes must explicitly flag this as unverified.
5. **The correct sequence is: Build → Deploy → Verify → Fix → Document → Onboard** — This epic did: Build → Document → Mark done → User discovers it's broken.

## Lessons for Future Projects

1. **"Tests passing" ≠ "It works"** — Automated tests validate code logic, not production readiness
2. **Deploy before documenting** — Documentation should describe verified behavior, not assumed behavior
3. **The person who builds it should try to use it** — Or explicitly hand off verification with clear instructions
4. **Definition of Done must include the deployment context** — Especially for epics about deployment
5. **Dev agents have blind spots** — They can't access cloud environments, real databases, or deployed services. The workflow must account for this explicitly.

## Team Performance Summary

Epic 6 produced technically sound infrastructure, CI/CD, and documentation — but failed to deliver its core promise of a working deployed product. The gap between "code-complete" and "production-verified" was exposed when Mr. Door personally deployed the app and discovered 8+ production-blocking bugs. The team's definition of "done" was insufficient for deployment stories. This retrospective's most important outcome is the recognition that automated tests and code reviews are necessary but not sufficient — deployment verification must be an explicit step in the workflow.
