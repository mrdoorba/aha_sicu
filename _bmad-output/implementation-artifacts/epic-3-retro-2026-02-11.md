## What Didn't Go Well

### Data Convention Gaps
- Percentage value convention (0.5 = 0.5% vs 0.005) not defined upfront
- Caused formula rework in Story 3.9 (scoring system)
- Category name mapping (Indonesian data names vs English display) discovered late in Stories 3.9-3.10
- Root cause: correct-course workflow catches logic changes but not data format conventions

## Key Discussion Points

### Upfront Checks vs Review Process
- Mr. Door's perspective: "Upfront checks will introduce over-engineering when reviewing because the reviewer will look harder for mistakes. But if you guys want high standards then upfront checks should be more."
- Team consensus: Keep code review as primary quality gate, add lightweight dev self-check (2 questions) as a habit, not a formal gate
- Two-question self-check: (1) Is every AC tested? (2) Are error paths handled with structured codes?

### Data Convention in Correct-Course
- Mr. Door: conventions like percentage format "should check those in correct flow"
- Action: Add data convention verification step to correct-course workflow checklist

### Real-Data Validation Strategy
- Mr. Door: "We can wait for other brand validation when the current planning done and BD team starts using the web app. I will ask them to do one or two brand and check whether the calculators already correct. If it's lacking then we would just do fixes."
- Calculator fixes from BD team validation get fast-tracked (no full story cycle)

### Deployment Planning
- No deployment story existed in any epic — gap identified during retrospective
- Mr. Door confirmed deployment should happen after Epic 5 as a proper epic
- **Epic 6: Production Deployment & Launch** created (3-4 stories)
- Covers: infrastructure (Terraform), CI/CD (GitHub Actions), production testing, BD team onboarding
